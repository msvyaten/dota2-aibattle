# AIBattle × Dota 2 — отчёт по Schema v2

> Статус: **В РАБОТЕ** (валидация глубины). Обновлено: 02.06.2026. Машина: Windows / Shadow PC.
> Детальный лог прогонов: `docs/validation-v2-results.md`. Опирается на подтверждённые Phase 1 + Phase 2.
> Правило доказательства: цифра из финального стат-дампа ИЛИ строка из `console.<matchid>.log`. «На глаз» не считается.

---

## 1. Что добавляет Schema v2

Расширение управляемости агента после доказанной базовой концепции (промпт → поведение).

- Управление стало **непрерывным (0–1)** — «диммер» вместо «выключателя».
- Набор: **6 диалов** — `harass_desire`, `farm_focus`, `forwardness`, `ability_aggro`, `rune_control`, `retreat_caution`.
- Второй тип управления — **правила** (событие→действие): `respawn_behavior` (телепорт к вышке / на линию / пешком).
- На ветке (спят до своей валидации): `execute_threshold` (добивание ультом), адаптивные `item_rules`.

Цепочка без изменений: `промпт → LLM → JSON → playstyle_*.lua → поведение бота`.

---

## 2. Методология

Зеркальный 1v1 Sniper vs Sniper. Для глубины — **прицельные A/B-прогоны на один диал**: оба бота
идентичны кроме ОДНОГО тестируемого диала (один LOW, другой HIGH), сравниваем player_slot 0 (Radiant)
vs 128 (Dire) в одном матче. Это 1 игра на тест вместо 2. Базовый симметричный харнесс в `playstyle_*.lua`.

## 5. Ключевые находки (почему laning-диалы буксуют)

1. **harass_desire — это кластер laning+retreat, а не диал-ордеринг.** Снайперы не сходятся на
   дистанцию автоатаки (~550): фармят на рейндже, герои в ~1000+ за крипами. Ветка «бить героя, если
   в радиусе» не триггерится. Чтобы харас работал — бот должен ПОДХОДИТЬ к герою, но это сцеплено с
   retreat: подошёл → получил урон → `mode_retreat` (retreat_caution) увёл назад = «выстрелил и отбежал».
2. **Денаи ≈ ласт-хиты** из-за асимметрии радиусов в `GetDesire`: свои крипы сканируются в **1200**,
   вражеские — в **800**. Стоя сзади, бот денаит (видит на 1200), но не дотягивается до добивания (800).
3. **Игры тянутся 30+ мин.** Киллов нет (боты пассивны), вышка падает от крипов поздно → долго.
   Победа в 1v1 = 2 килла ИЛИ вышка; нетворт ни при чём.
4. **TP докупаются стоковой логикой OHA** (не наша настройка), бесполезно в 1v1 (`teleports_used` обычно 0,
   свитки копятся). Разница «5 vs 2» — таймстейт золота, не конфиг.

## 6. Открытые задачи

- **Починить `respawn_behavior = tp_to_tower`** (держать гард, пока ТП не дочанелён).
- **harass/aggression** — позиционный подход к герою + связка с retreat (целый кластер laning-поведения).
- **rune_control** — подтвердить (длинная игра / усилить rune-desire vs арбитраж).
- **retreat_caution, forwardness** — прогнать чисто.
- **Вышки (на будущее):** бот не доламывает вражескую вышку, чтобы победить. Пример (8835417950, ~29 мин):
  у вышки Radiant 1 тычка до сноса, крипы под вышкой (урона ему бы не было) — бот проигнорировал, мог выиграть.
- **Свести laning-поведение OHA холистически** — текущие диалы тонкие, упираются в пассивную базовую логику.

**Отложено в v3:** командные диалы (5v5), `execute_threshold` + `item_rules` (на ветке, спят),
плавная градация `forwardness`, генерация item-сборок из промпта.
